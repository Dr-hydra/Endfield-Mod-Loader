# E Mod Loader 使用指南

## Windows

1. 从 [Release](https://github.com/Dr-hydra/Endfield-Mod-Loader/releases/latest) 下载 Windows ZIP，完整解压到独立目录，运行 `EModLoader.exe`。
2. 点击“导入 ZIP”，选择作者提供的完整模块包。新模块默认停用，确认后开启模块开关。
3. 打开模块页面保存配置；没有网页的模块可使用配置编辑器。
4. 确认主界面的游戏路径，点击“启动游戏”，等待界面显示游戏宿主连接。

模块网页需要 Microsoft Edge WebView2 Runtime。软件数据默认保存在 `%LOCALAPPDATA%/EndfieldModLoader/`，可通过“打开数据目录”访问。

Windows 会保存选择的 `Endfield.exe`，下次启动直接使用。未保存或路径失效时，从卸载注册表和常见安装目录自动查找；多个安装需手动选择，也可以使用“选择…”指定路径。游戏路径与 XInput 共存开关位于数据目录的 `launcher.json`。

Windows 0.1.4-dev 支持多官方启动器选择（自动识别鹰角国服、Bilibili服、全球服 Gryphline、Epic 渠道或自定义启动器）以及“无启动器（Bypass 模式）”直接启动。界面新增“启动器”下拉列表与浏览按钮，配置将自动保存在 `launcher.json` 中。
- **自动/官方启动器**：满足新版客户端官方父进程检查，游戏退出后自动清理桥接进程。
- **无启动器（Bypass）**：无需运行或安装官方启动器即可直接启动游戏。
- 启动器选择与游戏路径联动，支持实时自动探测与记忆。

0.1.2 新增“保留其他 XInput DLL 并加载 EML”，位于游戏路径下方。默认关闭，勾选或取消会自动保存。游戏目录已有其他工具的 `xinput1_4.dll` 时，开启后点击“启动游戏”，EML 保留原 DLL，再额外加载自己的 Host。详情见 [XInput 共存设置](XINPUT_COEXISTENCE.md)。

Windows ZIP 内置 .NET 运行时，主程序旁仅保留 `runtime` 中的四个启动组件和说明、许可文件。完整解压并保留目录结构即可使用。

游戏启动返回 `740` 时，EML 自动请求 Windows UAC 确认，只提升启动组件权限，主界面保留原权限。取消确认会停止此次启动；不会反复弹出请求。启动前关闭已有游戏进程。

### DLL 自启动

1. 关闭游戏，确认游戏路径并点击“安装 DLL 自启动”；写入权限不足时确认 UAC。
2. 安装后可以从官方启动器或游戏快捷方式启动，无需先打开 EML。
3. 要移除时关闭游戏，在 EML 点击“卸载 DLL 自启动”。

安装创建游戏目录中的 `xinput1_4.dll` 和 `eml-xinput.json`，代理转发系统 XInput 调用并启动 EML Host。卸载核对归属和 SHA-256，只删除 EML 的安装内容；其他工具或被修改的同名 DLL 不会被覆盖、删除。

自启动记录指向 EML 安装目录和模块库。移动 EML 目录或更换数据目录后重新安装自启动。已安装 EML 代理时，主界面“启动游戏”使用该代理，不重复注入；已有其他工具的 XInput 代理时按共存开关决定是否启动。共存开关不会允许安装或卸载功能覆盖、删除其他工具的 DLL。

## Android

需要 Android 10 及以上、ARM64 和支持 libxposed API 102 的兼容框架。

1. 安装 APK，在框架中启用 E Mod Loader，并选择实际使用的终末地客户端作为作用域。
2. 在 EML 应用中导入模块 ZIP，开启模块并保存配置。
3. 彻底停止并重新启动游戏，使框架与原生宿主加载模块。

单独安装 APK 不会启用游戏功能。当前 APK 使用开发签名；框架接入、配置更新和游戏内效果尚未经过设备验证。

## 模块管理

| 操作 | 行为 |
| --- | --- |
| 启用 / 停用 | 开始或结束模块生命周期；停用时请求模块恢复其状态 |
| 配置 / 模块页面 | 保存本模块的 JSON 配置或使用作者提供的网页 |
| 排序 | 调整模块列表顺序；声明的依赖仍决定必要的启动先后 |
| 同 ID 更新 | 安装新代次，保留配置及启用状态；已加载原生库需要重启 |
| 移除 | 移除安装记录；已加载原生代码保留至进程退出 |
| 日志 / 状态 | 查看连接、模块错误、依赖和需要重启的提示 |

模块默认配置只在首次安装时应用。升级时新增配置字段的默认值由模块作者处理。

DLL / SO 不进行热卸载。某些模块需要在后续游戏帧恢复相机、模型等状态；暂停期间的收尾可能要等游戏恢复。

## 离线宿主与游戏宿主

“启动离线宿主”在独立测试进程运行模块，用于检查包、网页、配置与消息通信。离线连接不代表已连接游戏；依赖游戏接口的功能会等待运行时或报告不可用。

Windows 启动游戏时会停止由应用启动的离线宿主。第一人称等游戏功能只能在真实游戏宿主中生效。

## 第一人称

加载器和第一人称模块是独立下载项。导入 `example.first-person-0.1.0-dev.zip` 后启用模块，再在模块页面设置功能。

- Windows 默认使用减号 `-` 切换，要求游戏窗口获得焦点；热键可修改或关闭。
- Android 可保存“默认进入第一人称”；当前没有游戏内触控按钮。
- 默认不切换视角。头部隐藏与颈口填补依赖当前角色骨骼、网格及游戏接口。
- 暂停期间若相机更新停止，退出后的恢复等待后续游戏帧。

参数与构建说明见 [第一人称模块](../examples/first-person/README.md)。

## 常见问题

**网页无法打开：** Windows 检查 WebView2 Runtime；检查模块包是否包含清单指定的 HTML 和本地资源。

**等待游戏运行时：** 离线模式下属于正常状态。游戏中检查框架作用域、游戏宿主连接与模块日志。

**等待依赖：** 安装并启用模块声明的依赖；EML 不自动下载依赖包。

**接口不匹配或加载失败：** 检查模块支持的平台、游戏版本及日志。包格式兼容不代表模块使用的游戏函数兼容。

**更新后提示重启：** 结束当前宿主或游戏，再重新启动。已加载的二进制继续使用原安装代次。
