# 游戏加载方式：待定

已完成第一轮 [加载机制调研](LOADING_RESEARCH.md)：原第三方模块 Host 已用独立工程构建，并通过无游戏依赖的 Echo 回归。建议保留模块加载核心，独立改造产品入口、公开 SDK 和平台接入；改名不提供反作弊关联隔离保证。下面保留原迁入阶段的待决策边界，新产品尚未实现游戏接入。

已确定：E Mod Loader 与 BE 为不同产品，按最新选择不实现跨产品互斥，不共用锁或握手，也不保证同时使用的兼容性；EML 保留自身重复初始化保护。BE 移除第三方模块功能，但保留通用 Host、内置模块加载和共享 Hook 链设计。

当前产品仍处于原样迁入与调研阶段。不要据此宣称已可独立进入游戏、已更换协议/签名、或已完成第一人称独立模块化；独立离线 Host/Echo 验证见调研记录。

## Windows 候选

1. 显式启动加载：用户从 E Mod Loader 启动游戏，加载自己的运行时。加载器与模块生命周期分开；游戏已启动时的处理需要明确。
2. 代理自加载：安装一个代理入口，由游戏正常加载后启动自己的运行时。需要明确安装、卸载、更新及与已有代理的冲突处理。

不在本阶段复制 BE 的注入器或代理作为新产品实现，不执行游戏加载或部署。

## Android 候选

基于独立框架模块进入游戏进程。需要选定框架接口、产品包名、配置/资源发布机制以及游戏内 native library 的加载归属。
